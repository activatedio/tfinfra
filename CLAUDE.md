# tfinfra

A code-generation library for Terraform providers over AIP-shaped gRPC APIs.
Declare API resources and their behavior in Go over the **published protobuf
Go types**; the generator reads field metadata via **protoreflect at
generation time** — no protoc plugin, no proto files, no buf in the consumer —
and emits Terraform Plugin Framework provider code plus a thin runtime layer.

Sibling of `datainfra` / `apiinfra` and built on the same
`github.com/activatedio/gen` registry. The CLI counterpart is `cmdinfra`
(planned); the first consumer is `terraform-provider-authwise`.

## Repo layout

```
genlib/           # build-time code generation (panics on error)
  tf/
    types.go      # Spec, Entry, markers (Resource, DataSource, DataSourceList), Get/HasImplementation
    ops.go        # Ops bitmask (OpGet|OpList|OpCreate|OpUpdate|OpPatch|OpDelete; zero = all)
    fields.go     # protoreflect normalization: message descriptor + markers -> []Field
    registry.go   # NewRegistry(), Spec directory handler, FileMain file handler
    schema.go     # <Entity>ResourceSchema() emitter
    model.go      # <Entity>Model struct + ToProto/FromProto emitters
    names.go      # snake/camel helpers
pkg/              # runtime imported by generated code (returns errors)
  tf/
    scope.go      # Scope: AIP parent/name compose + parse, identifier attributes
examples/petstore # end-to-end example; generated/ is the golden output contract
  proto/          # toy proto (buf; regeneration is manual, output committed)
  gen/main.go     # generator entry point (//go:generate go run .)
  generated/      # generated golden output
```

## Generation flow

1. The consumer's `gen/main.go` builds a `*tf.Spec`: one `tf.Entry` per API
   resource over the published pb Go type
   (`reflect.TypeFor[identitypb.Realm]()`), with markers declaring what to
   generate and the behavioral layer (`Required`, `Immutable`, `Computed`,
   `Sensitive`) that AIP protos without `google.api.field_behavior` cannot
   express.
2. `tf.NewRegistry().RunDirectoryPathHandler("../generated", spec)` walks the
   entries; each entry with a `Resource` marker gets a `<entity>_gen.go`.
3. For each file, the `*FileMain` file handler runs `NormalizeFields`
   (protoreflect: names, kinds, cardinality, enum values; Go binding read
   from the protoc-gen-go struct tags) and emits the schema and model
   sections.
4. Everything runs from `go generate ./...` — the consumer needs no proto
   toolchain, because pb descriptors ship inside the compiled types.

All generated files carry a `// Code generated by
github.com/activatedio/tfinfra. DO NOT EDIT.` header (`golangci-lint`'s
`generated: lax` recognizes them).

## Handler registry

`tf.NewRegistry()` returns a `gen.Registry` with:

- A **directory handler** keyed on `*tf.Spec` — owns the target directory,
  opens one file per Resource entry.
- A **file handler** keyed on `*tf.FileMain` — composes the file's sections.
  Consumers can register additional file handlers on the same key via
  `Registry.WithHandlerEntries` to append code to generated files without
  forking the library (handlers on one key concatenate).

## Markers

| Marker              | Generates                                                    |
| ------------------- | ------------------------------------------------------------ |
| `tf.Resource`       | resource schema + model + conversions (CRUD glue pending)    |
| `tf.DataSource`     | PENDING: singular data source (Get by name)                  |
| `tf.DataSourceList` | PENDING: plural data source (List under parent)              |

`Resource` behavior lists reference proto field names (snake_case); unknown
names, conflicting behavior, and unsupported shapes all **panic at
generation time** — failures must be loud, never silent omissions.

## Scopes

`pkg/tf.Scope` models the AIP hierarchy as ordered parent collection names
(`tf.NewScope("tenants", "issuers")` → parents `tenants/{t}/issuers/{i}`,
identifier attributes `tenant_id`, `issuer_id`). tfinfra predefines no
scopes — each consumer declares its service's scope table next to its spec.
Scope identifier attributes are generated as optional `RequiresReplace`
strings on every resource schema.

## Supported field shapes (first pass)

| proto                       | attribute                    | model            |
| --------------------------- | ---------------------------- | ---------------- |
| string                      | StringAttribute              | types.String     |
| bool                        | BoolAttribute                | types.Bool       |
| int32/64, uint32/64, fixed* | Int64Attribute (widened)     | types.Int64      |
| float/double                | Float64Attribute             | types.Float64    |
| enum                        | StringAttribute + OneOf      | types.String     |
| repeated string             | ListAttribute[String]        | types.List       |
| map<string, string>         | MapAttribute[String]         | types.Map        |
| google.protobuf.Timestamp   | StringAttribute (RFC 3339)   | types.String     |

Anything else (nested messages, repeated messages, Struct, Any, bytes, real
oneofs, non-string lists/maps) panics with a "not yet supported" message.

**Read-side null convention** (to be refined with proto3 `optional`
presence in the CRUD runtime task): strings, enums, lists, maps, and
timestamps read a proto zero value as Terraform null — except `name` and
`Required` fields, which always carry a value. Bools and numbers always
carry a value, because proto3 cannot distinguish zero from unset.

## Status

Implemented: repo bootstrap, spec model, Ops, Scope runtime
(compose/parse/identifiers), protoreflect normalization, schema emitter,
model emitter, golden example, determinism (regeneration is
byte-identical).

Pending (tracked in the terraform-provider-authwise plan, tasks #4–#7 and
#13): CRUD resource glue (Create/Read/Patch+update_mask/Delete/Import
delegating to a pkg CrudTemplate), data sources, context resolvers wired to
provider config, client_credentials auth (ships in
`api-client-go/credentials/bearer`), update-mask computation, Struct/Any
via jsontypes, write-only arguments, association resources, Wiring/index
generation.

## Working in this repo

```sh
# Regenerate the example (the golden output contract):
( cd examples/petstore/gen && go run . )

# Regenerate the example's pb types (only after editing the toy proto;
# output is committed):
( cd examples/petstore && buf generate )

# Test / format / lint:
go test -cover ./...
make fmt
golangci-lint run --timeout 2m
```

- After changing anything in `genlib/tf/`, rerun the generator and verify
  the diff in `examples/petstore/generated/` — CI diff-checks it.
- Unit tests are table-driven `map[string]s` with `arrange`/`assert`
  closures; `assert` takes the subtest's `*testing.T`; units are built
  inside `t.Run`; tests live in external `_test` packages.

## Style

- Generator code panics via `gen.Check` / `panic(...)` for build-time
  errors — fine in `genlib/`, never in `pkg/`.
- Runtime code in `pkg/` returns errors, never panics.
- Public types carry godoc comments; package-level docs live in `doc.go`.
- Treat `examples/petstore/generated/` as the output contract for
  downstream consumers.
